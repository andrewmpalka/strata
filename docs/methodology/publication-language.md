# Publication language

Public analytical language must not exceed the evidence.

- Say “associated with retention,” never that an authentication mode improves,
  causes, drives, or produces retention.
- Claims stay on observed authentication mode and observed chain activity. Do
  not describe these observations as product `onboarding`; account-creation or
  registration claims require direct evidence and declared coverage.
- `crypto-new` is prohibited because absent observed history is a mixed,
  censored category.
- Do not call the coordination strictness threshold `precision`.
- Apply the terminology checks to generated identifiers, analytical output,
  dashboard copy, new findings, and ordinary user-facing documentation. Keep a
  narrow allowlist only for the canonical specification, archived review
  material, tests of the prohibition, and explicit limitations that discuss a
  prohibited term.
- Cross-chain results are directional only; do not imply identical account,
  exposure, or activity semantics.
- Use `direct_address_transfer`, not “internal transfer” or wording that implies
  ownership.
- Dashboard and findings text identify the run, population, coverage, maturity,
  suppression, and limitations needed to interpret each number. Never relabel
  absent or refused results as zero.

When no qualifying live analytics run exists, `FINDINGS.md` must state exactly:

> No empirical study findings are published because no qualifying live analytics run exists yet.
